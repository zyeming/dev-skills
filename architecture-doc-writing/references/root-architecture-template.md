## 12. 扩展指南

只写会保护全局边界的扩展步骤。普通开发流程、API 字段和模块内部实现细节不放在根文档。

新增模块时：

1. 定义责任和非责任。
2. 定义数据所有权。
3. 定义公开入口。
4. 定义允许的依赖方向。
5. 定义事务、一致性、事件和幂等策略。
6. 必要时新增模块级架构文档。

新增功能时：

1. 找到 owning module。
2. 使用现有公开入口或应用服务。
3. 保留事务边界。
4. 保留幂等和状态机规则。
5. 保留安全和授权检查。
6. 如果边界、所有权、状态、事件或不变量变化，更新架构文档。

## 13. AI Coding Contract

修改本项目时：

1. 先读本文件。
2. 如果目标模块有架构文档，先读目标模块的架构文档。
3. 保留模块边界。
4. 保留依赖方向。
5. 保留数据所有权。
6. 保留事务边界。
7. 保留关键流程的幂等性。
8. 保留状态机校验。
9. 保留授权和租户隔离。
10. 不要把业务规则放进 controller、route、job、repository 或 adapter。
11. 不要直接访问其他模块的 repository 或表。
12. 不要在已有应用服务可以扩展时创建重复服务。
13. 不要引入承载业务逻辑的全局 utility。
14. 不要在未明确要求时改变公开 API 行为。
15. 如果必须违反本文档，先新增或更新 ADR。

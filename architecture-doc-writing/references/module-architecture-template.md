# 模块级 ARCHITECTURE.md 模板

用于模块、服务、package、bounded context 或子系统。

模板是删减清单，不是必填清单。默认输出应该短于模板；只保留能保护边界、所有权、不变量、状态、事务、幂等、安全或扩展路径的章节。

写作前先把候选信息分成：

- `必须写`：不写会导致未来修改破坏架构约束。
- `一句带过`：有上下文价值，但不是核心约束。
- `引用已有文档`：API、字段、前端流程、README、测试或 ADR 已经更适合承载。
- `不写`：只是代码导览、目录说明或普通实现细节。

## 12. 常见变更模式

只保留高频且容易破坏架构的变更路径。普通新增接口、字段或查询不需要写成流程。

### 新增状态

必须更新：

1. 状态枚举或常量。
2. 状态机流转规则。
3. 状态相关校验和测试。
4. 事件、回调或后台任务中的状态处理。
5. 本文档。

禁止：

- 只新增 enum value，不更新状态机。
- 直接修改状态字段绕过流转校验。

### 新增外部 provider

必须更新：

1. 新增 provider adapter。
2. 实现稳定 provider interface。
3. 转换 provider-specific error。
4. 处理幂等、重试和 callback。
5. 增加失败、重试、回调相关测试。

禁止：

- 从业务逻辑直接调用 provider SDK。
- 将 provider-specific 字段泄漏进核心领域模型，除非明确需要。

### 新增查询

优先方式：

- 增加到本模块 query service 或 read model。

禁止：

- 为了方便让其他模块直接访问本模块内部表或 repository。

## 13. AI Coding Notes

只写修改本模块时最容易被 AI agent 破坏的约束。不要重复上文所有内容。

修改本模块时：

1. 使用上文列出的公开入口。
2. 保留模块所有权。
3. 不要向其他模块暴露内部实体。
4. 不要绕过状态机校验。
5. 不要削弱幂等性。
6. 不要把业务逻辑移入 infrastructure code。
7. 如果责任、状态、事件、事务边界或外部依赖变化，更新本文档。

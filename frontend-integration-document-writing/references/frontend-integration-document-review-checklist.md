# 前端接入文档 Review Checklist

检查目标是让未参与后端设计的前端工程师无需回查后端源码即可完成接入。只检查与实际能力有关的项目，不为覆盖清单增加空章节。

## 事实来源与范围

- [ ] 已区分当前契约与目标契约，没有把未实现目标写成当前行为。
- [ ] 当前行为由真实 HTTP 入口、公开类型、校验、枚举和调用方支持。
- [ ] 目标行为来自用户确认、已批准需求或明确采用的设计；`Draft` 没有被当成最终事实。
- [ ] 不同资料对字段、脱敏、权限、状态、兼容或发布结论的冲突已解决或明确报告，没有静默选择。
- [ ] 目标文件与只读参考区分清楚，没有误改参考文档或业务代码。
- [ ] 适用端、接入能力和不包含的 UI 或后端实现范围清楚。

## API 覆盖与变化

- [ ] API 总览覆盖全部新增、变化、语义变化、不变但重要、废弃的接口。
- [ ] 总览与正文中的方法、路径和 API 数量一致。
- [ ] 每个 API 分别说明请求变化和响应变化。
- [ ] 结构不变但权限、过滤、排序、状态、副作用或成功含义变化时，已标记为语义变化。
- [ ] 新版不应继续使用的旧路径、旧字段、错误大小写、旧枚举或兼容参数已明确列出替代方式。

## 输入与输出契约

- [ ] 每个 API 写明方法、路径、鉴权和参数位置。
- [ ] 请求字段包含完整字段路径、实际 wire 类型、必填条件、默认值、允许值、长度或数量限制和变化标记。
- [ ] 响应字段包含完整字段路径、实际 wire 类型、必返或可空、条件返回、顺序和变化标记。
- [ ] 现有接口的重要不变字段已明确列出，没有使用无文内引用的“其他字段不变”。
- [ ] 共享大型对象只完整定义一次，引用接口的差异仍然清楚。
- [ ] 公共响应包装、分页、时间、空数组、`null` 和错误结构与真实项目一致，没有从其他项目照搬。
- [ ] JSON 示例使用完整且有效的字段组合，没有真实 Token、患者信息、手机号、密钥或生产域名。

## 前端调用行为

- [ ] 不同端、入口、路由或 Scheme 对应的 API、类型和上下文字段清楚。
- [ ] 名称相近字段、不同 ID、大小写以及 Query/Path/Body 位置不会混淆。
- [ ] 分页、加载更多、搜索、排序、跨页选择、去重和返回顺序在相关时写清。
- [ ] 状态、权限、提醒和 `can*` 字段以服务端为准，文档没有要求前端自行推断。
- [ ] 首次进入、内容渲染、页面重新可见、主动刷新和状态操作成功后的调用时机清楚。
- [ ] 超时是否重试、幂等范围、状态冲突后的刷新对象和失败时保留的输入清楚。
- [ ] “创建成功”“受理成功”“通知送达”“已读”“已确认”“已完成”等成功口径没有混用。

## 异常、兼容与发布

- [ ] 主要失败场景写明前端动作，而不是只罗列后端错误。
- [ ] 未确认的错误码、文案、时间格式、默认值、回退行为或未知枚举策略没有被编造。
- [ ] 历史数据、旧客户端、旧字段和混合版本行为清楚。
- [ ] 后端前置版本、消费者发布顺序、动态页面和回滚限制在相关时写清。
- [ ] 外部通知、异步任务或第三方副作用是否属于接口成功条件已经明确。

## 可读性与交付

- [ ] 文档按“公共约定和总览 → API → 流程 → 异常兼容 → 联调”自然展开。
- [ ] 字段和固定映射使用表格，调用顺序使用编号或短流程，图只在明显降低复杂度时存在。
- [ ] 同一字段、状态、公共对象或规则只完整定义一次。
- [ ] 表格内容没有在下文逐行复述；保留的补充文字只说明前端动作和例外。
- [ ] 没有数据库、SQL、Mapper、内部类、内部 DTO 传递和调查流水账。
- [ ] 没有组件结构、视觉样式、按钮位置、表单布局等普通 UI 设计。
- [ ] 空章节、模板说明、占位符和失效结论已删除。
- [ ] Markdown、本地链接、代码围栏、字段名、方法和路径均有效。
- [ ] 前端工程师能够只看本文确定调用接口、完整参数、响应解析、刷新与失败处理。

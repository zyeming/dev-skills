## 裁剪规则

- 没有跨接口公共规则时删除“公共类型与规则”。
- 单端文档不增加空的端分类；多端共享 API 时完整契约只定义一次，再列差异。
- 没有废弃调用、发布依赖或历史兼容时删除对应内容，不写“无”。
- 不为只有一个字段的简单请求机械增加 JSON 示例。
- 同一字段或规则只完整说明一次，其他位置通过章节或字段路径引用。
- 成稿不能出现未确认的错误码、默认值、时间格式、生产配置或脱敏规则。

## 字段变化标记

| 标记 | 使用条件 |
| --- | --- |
| 新增 | 新版增加，旧后端不接受或不返回 |
| 变化 | 字段已存在，但类型、必填、默认值、约束、返回条件或含义改变 |
| 语义变化 | wire 结构不变，但权限、筛选、排序、状态、副作用或成功口径改变 |
| 不变 | 前端仍需使用且 wire 契约与含义不变 |
| 废弃 | 新版不应继续使用，但可能为旧客户端暂时保留 |

## 成稿整理

1. 删除空章节、模板说明和未替换占位符，并重新连续编号。
2. 确认 API 总览数量与正文 API 数量一致。
3. 确认每个 API 的完整输入、输出、条件返回和变化标记能够独立理解。
4. 合并重复的公共对象、状态和规则；不删除调用时机、失败恢复和兼容边界。
5. 删除后端内部实现、源码调查过程和普通 UI 交互描述。

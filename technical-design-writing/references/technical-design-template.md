# Technical Design 模板

本模板提供默认阅读顺序和常用格式，不要求机械套用。根据实际内容选择图、表格、列表或短段落；没有内容的小节删除并顺延编号。无论采用什么格式，都必须保留数据模型、API 契约、服务归属、关键实现规则和上线边界。

模板中的说明和占位符只用于写作，不能原样保留在成稿中。项目已有结构优先于本模板。

## 格式选择

- 需要逐项精确对齐的字段、契约、配置、任务和固定映射使用表格。
- 同一主题下有 2～4 个并列结论时使用一级 bullet；一个列表混合多个主题时，按主题使用一级 bullet，再用二级 bullet 展开。
- 操作和发布存在先后依赖时使用编号列表。
- 总体说明只有在增加结论、范围或关键边界时保留；如果只是复述下方图或表，直接删除。
- 图示只用于降低跨服务调用、实体关系或异步时序的理解成本，不能代替正文中的字段和行为定义。

## 成稿整理

1. 只看标题，确认能够顺着“数据模型 → 前端变化 → 后端实现 → 上线准备 → 其他实现注意点”理解方案。
2. 确认每个 API 都写明提供服务、接口变化和必要的请求、返回字段变化。
3. 确认数据库结构变化保留完整 DDL，并与数据模型字段一致。
4. 删除重复出现的字段、共享对象和业务规则；图表已经说明的内容不再复述。
5. 删除源码调查过程、普通方法清单、内部 DTO 传递链和对读者没有设计价值的写作说明。
6. 将宽泛概念改成具体的数据、状态、责任或行为；标准技术术语不做多余解释。
7. 删除内容后，再次确认契约、决策、风险、兼容和回滚边界没有丢失。

# Team AI Coding Standards

Companion reference for the code-review skill. Apply when the diff touches AI-generated code, protected files, dependencies, bug fixes, or PR metadata.

---

## Protected Files

Flag diffs that modify the following paths because they need explicit human attention:

| Pattern                                            | Review concern                                                      |
| -------------------------------------------------- | ------------------------------------------------------------------- |
| `migrations/*`, `db/migrations/*`                  | Schema/data changes can be hard to reverse                          |
| `infra/*`, `terraform/*`, `k8s/*`                  | Production environment impact                                       |
| `.github/workflows/*`                              | CI/CD and supply-chain security risk                                |
| `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml` | Must match manifest changes and be generated by the package manager |
| `.env`, `.env.*`, `*.pem`, `*.key`                 | Secrets or secret-adjacent material                                 |

Output format:

```markdown
[HIGH] Protected file modified
File: .github/workflows/deploy.yml
Issue: CI/CD changes can affect release or supply-chain behavior.
Fix: Require explicit human review for this file before merge.
```

## Security-Sensitive Areas

If changes touch any of the following, flag for stricter review in addition to normal PR approval:

- Auth/authorization logic (JWT, OAuth, session)
- Payment processing
- Crypto/key management logic
- User data operations, especially PII read/write/delete
- Raw SQL query construction
- External URL fetching, webhook handling, or file upload/download paths

Output format:

```markdown
[HIGH] Security-sensitive area modified
File: src/auth/jwt.service.ts
Issue: Auth logic changes carry elevated production risk.
Fix: Require specialized security review beyond normal approval.
```

---

## New Dependency Added

When a new package appears in `package.json`, `pyproject.toml`, or `requirements.txt`:

1. Check whether the dependency is necessary or the existing stack can solve the problem.
2. Check whether the diff or PR text explains why the dependency is needed.
3. Treat auth, crypto, HTTP clients, parsers, serialization, file handling, and security-sensitive packages as higher risk.

Do not require live download counts or CVE checks unless the user asks for that research or the information is already available.

Output format:

```markdown
[HIGH] New security-sensitive dependency lacks justification
File: package.json
Issue: Added HTTP client dependency without explaining why the existing stack is insufficient.
Fix: Add a dependency justification and review SSRF handling before merge.
```

## Bug Fix Without Reproducing Test

When the diff is a bug fix but no new test would fail on the unpatched code, flag it unless the change is trivial or the PR explicitly justifies why a regression test is not practical.

Output format:

```markdown
[HIGH] Bug fix missing reproducing test
File: src/users/users.service.ts
Issue: The fix has no regression test that would fail before the change.
Fix: Add a focused reproducing test or document why it cannot be tested.
```

---

## Duplicate Code Blocks

AI-generated code often repeats plausible blocks. Flag repeated blocks of similar logic when extracting or reusing a helper would reduce real maintenance risk.

Output format:

```markdown
[MEDIUM] Duplicate code block
Files: src/orders/orders.service.ts:45, src/invoices/invoices.service.ts:32
Issue: Two services now contain the same non-trivial business logic.
Fix: Extract the shared behavior or explain why the duplication is intentional.
```

## Project Config Audit

Use only in `--audit` mode or when the user asks for project hygiene review.

| Check                               | How to verify                                                | Pass condition                       |
| ----------------------------------- | ------------------------------------------------------------ | ------------------------------------ |
| Project instructions exist          | Look for `AGENTS.md`, `CLAUDE.md`, or repository review docs | Present where expected               |
| Architecture guide is concise       | Inspect `ARCHITECTURE.md` if present                         | Short enough to guide agents         |
| Dangerous automation is constrained | Inspect agent/tool settings if present                       | Destructive actions require approval |

Output format:

```markdown
[MEDIUM] Project review guide missing
File: AGENTS.md
Issue: No repository-level review or coding instructions were found during audit.
Fix: Add concise project instructions for review, validation, and protected files.
```

---

## PR-Only Signals

Apply only when reviewing a PR or branch with commit/PR metadata available:

- Commit messages should follow the repository's convention when one exists.
- PR descriptions should identify AI-assisted areas when the team requires that disclosure.
- Security-sensitive or AI-generated code should identify areas needing extra human attention.

Output format:

```markdown
[LOW] AI-assisted areas not disclosed
Issue: The PR does not identify which modules were AI-assisted.
Fix: Add a short disclosure section listing AI-assisted files and areas requiring careful review.
```
